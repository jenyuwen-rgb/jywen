全台各級泳協賽事監控與成績採集中樞 核心定時任務

執行頻率：每天清晨 06:00:00 (Asia/Taipei)
調度鬧鐘： Cloud Scheduler (swim-daily-0600-schedule)
執行單元： Cloud Run Job (swim-daily-crawler)
同步目標： GCS Bucket (3 個核心 JSON)
▸ CTSA 中華泳協官方全國賽事即時監控與採集：每日連線官方系統 (game_data.aspx) 監控 115 年度最新賽事發布狀態，遇新賽事完賽自動增量解析成績與選手名冊入庫。
▸ 7 大就緒泳協與委員會歷屆賽事目錄對齊：維護 CTSA(全國)、TPESA(台北)、NTPC(新北)、SWIM8(台中)、TAINAN(台南)、KCC(高雄)、SWIM_KCSAT(高雄水上) 共 7 大協會之歷屆賽事目錄與成績爬取支援。
▸ 115 年度官方賽事實體行事曆維護：維護官方核定之 115 年 96 場賽程時間表 (calendar.json)，提供月曆即時檢索。
▸ 雲端自愈與自動熔斷保護：遇官方網站改版或連線逾時，觸發 Gemini 智慧診斷與 3 次硬性物理熔斷，確保系統零當機。
2

AI 異常偵測與自動自愈修復引擎 (Cloud Self-Healer) 智能守護

執行頻率：事件觸發（遇官網改版或異常時秒級喚醒）
自愈大腦： Gemini LLM (智慧 HTML 診斷)
熔斷限制： 最多重試 3 次 (MAX_RETRY_LIMIT=3)
保護機制： 超額立即物理熔斷 + 現場 Snapshot 封存
▸ 官網版面突變自愈：若泳協官網更改 HTML 標籤或選擇器導致爬取為空，自動傳送最新 HTML 片段至 Gemini 進行智慧分析並重生規則。
▸ 3 次硬性物理熔斷：為防止無窮重試消耗 API 配額，設定 3 次上限，超過即停止並留下完整錯誤堆疊。
3

多端無伺服器靜態資源分發 (Serverless Edge Distribution) 邊緣分發

執行頻率：7×24 小時常駐高可用存取
儲存服務： Google Cloud Storage (GCS)
快取原則： Cache-Control: no-cache (零快取即時更新)
存取協議： HTTPS CORS 公開唯讀 REST
▸ 純靜態無伺服器架構 (方案 B)：爬蟲跑完直接將 JSON 檔案推入 GCS，前端 Vercel PWA 透過瀏覽器直接向 GCS 抓取，免除雲端常駐虛擬機（VM）或資料庫連線維護開銷。
▸ 零延遲與零快取：透過 HTTP Header no-cache, no-store 確保全台選手家長與教練點開網頁永遠看到第一手最新賽事。
4

雲端結構化審計與健康日誌監控 (Cloud Logging & Audit) 審計監控

執行頻率：每次爬蟲作業啟動/完工時同步記錄
日誌平台： Google Cloud Logging 原生結構化格式
前端同步： GCS crawler_error_logs.json
監控指標： HEALTHY / FAILED 與執行秒數
▸ 透明可視化稽核：將每次採集之賽事筆數、各協會狀態、耗時毫秒數發布至 GCS，供本頁下方「GCP 爬蟲執行與自愈修復日誌」終端機窗口即時讀取呈現。
